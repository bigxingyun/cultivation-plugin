## 常用命令（都在工作区根目录下跑）

```sh
npm run dev         # 开发模式启动（先 build 插件，再带 esbuild-register 启动）
npm run start       # 生产模式启动
npm run build       # 编译 external/ 下的插件到 lib/
npm run smoke       # 链路自检，13 项
npm run smoke:game  # 游戏全流程自检，55 项（退出码即结论）
npm run probe:style # 把 13 个数据界面的**原样输出**打出来（调排版用，不断言）
npm run gen         # 从 插件/基础/*.md 重新生成 src/data/*.ts（改了文档才需要跑）
```

启动成功后：控制台在 http://127.0.0.1:5140 ，沙盒在控制台左侧（可模拟发消息调试指令）。

## 调试技巧

**测试期想跳过等待**：改 `data/koishi.db`，把 `xianxia_queue.finishAt`、
`xianxia_chain.finishAt`、`xianxia_user.seclusionStart` 改成过去的时刻即可
（这就是惰性结算的好处）。

**管理员指令**需要 `authority ≥ 4`；在控制台沙盒里通常是够的，若提示「权限不足」，
就在控制台「用户管理」里把自己提权，或者干脆直接改数据库
（`xianxia_user.material` / `rank` / `exp`）。

**后期内容**（帝档任务、六品丹、链的后续章节）需要先跳到高境界才看得到。

**看排版**：改完输出跑 `npm run probe:style`，它会把 13 个数据界面的原样输出打出来。
自检只验数据落库，**排版问题它看不见**——上一轮 5 个输出 bug 里有 3 个是这个探针逼出来的。

## 输出分层（《游戏结构与命令设计.md》§4.4.1）

数据界面**只摆数据**，规则 / 获取途径 / "下一步做什么" 一律归 `帮助 <指令名>`
与末尾的 `▸ 待办` 行。所以 `.状态` 里不会出现「修为不增长，发闭关开始」，
`.历练` 菜单只有一行操作提示。自检第 40 项会扫描禁词。

**删一处必须在帮助或待办里补一处**，否则就是把信息弄丢了——这条也写进了
README 的坑表（「静默丢失信息」）。

- 排行榜 PvP、图片版帮助/介绍、飞升转生

**与设计文档的两处主动偏离**（都已记录理由）：
1. 数据表用自建 `xianxia_user`（主键 = 平台 `userId`），**没有扩展内置 `user` 表**。
   理由：不依赖 `session.user` 被加载，与已验证的 demo 插件同一套写法，更稳。
2. 采纳了 §7 差异清单的修正：金仙段按 **8 次突破**（折损 1.999）、链节点时长 = `T(境界起点)`、
   `ΣT(1..80)=856.9h`。（详见《游戏结构与命令设计.md》§7）

## 已查实的坑（本工作区亲自踩过，务必避开）

| 坑 | 症状 | 正确做法 |
| --- | --- | --- |
| **在 `set(table, query, (row) => ...)` 里用原生算术** | `(row.exp ?? 0) + x` **静默得到 NaN**——`row.exp` 返回的是 SQL 表达式对象，不是数字。整套数值链会一路 NaN 下去，且不报错 | 一律用 `$.add(row.exp, x)` / `$.add(row.material, -n)`，**绝不在回调里做原生加减** |
| `timestamp` 字段赋 `null` | TS 报 `Type 'Date \| null' is not assignable to Term<Date, boolean>` | 赋 `null` 时标 `as any`（读取时仍是 `Date \| null`） |
| `tsconfig` 继承根配置的 `module: ESNext` | 产物是 ESM，`lib/index.js` 里留着 `import`，纯 `node` 下 `require` 会炸 | 插件自己的 tsconfig 覆盖为 `module: CommonJS` + `moduleResolution: Node` |
| 装了旧的 `@koishijs/cli` | 全套 cordis 版本打架，`cannot resolve plugin`、`using.every is not a function` | **不要单独装 `@koishijs/cli`**，用 `koishi` 自带的 `koishi` 命令 |
| `data/` 目录不存在 | sqlite 驱动直接报 `database directory not accessible` | 先建目录 |
| 插件没有 `lib/` 产物 | 加载器报 `cannot resolve plugin "xxx"` | 改完源码先 `npm run build`（`npm run dev` 已内置） |
| `logger` 不是内置插件 | `cannot resolve plugin "logger"` | `npm i @koishijs/plugin-logger` |
| `@koishijs/client` 是 console 的 peer 依赖 | 控制台白屏 | `npm i @koishijs/client` |
| `dispose` 里用 `ctx.logger()` | 卸载时抛 `ctx.logger is not a function` | 模块顶层 `new Logger(...)` |
| `bot.session()` 传 `content: '字符串'` | payload 覆盖 Session 原型的 setter，前缀解析崩 | 传 `h('text', { content })`，或用官方 mock |
| 自检不删旧库 | 第二次跑报 `UNIQUE constraint failed` | 自检开头 `fs.rmSync(data/smoke*.db)` |
| 把工作区插件放进 `koishi.yml` 的 `plugins` | 插件没构建时，加载器**只打一行错误就跳过**，应用照常启动，很容易误判为"已加载" | 看启动日志的 `loader apply plugin <名字>` |
| `toLines` 把 `''` 也过滤掉 | 开场白与 `介绍` 的**段落空行被吞**，输出挤成一整块；`array.filter(x => x !== '')` 看着无害 | 只丢 `null`/`undefined`——空字符串是**故意的段落空行** |
| 惰性结算把"起点"当成"结算游标" | `settleSeclusion()` 每次交互都跑，若它把 `seclusionStart` 推到 now，则「出关 合计」「状态 已挂」**恒显示 0 秒** | 起点（`seclusionStart`）与游标（`seclusionLast`）必须分开两个字段 |
| `amount()` 只在大数上加千分位 | `+2009` 与 `+16,500` 混排，看着像两套格式 | 所有面向玩家的整数一律走 `num()` |
| 静默丢失信息：删了解释却没搬走 | 数据界面干净了，但「未闭关就白挂」这条**再也无处可查** | 删一处必须在 `帮助 <指令>` 或 `待办` 条目里补一处；自检第 40 项会拦禁词 |
