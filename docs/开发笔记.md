## 指令层级

玩家可见一级入口：`修仙` · `修炼` · `历练` · `每日` · `成长` · `故事` · `帮助` · `介绍` · `待办`（及 `修仙管理`）。
二级挂在父指令下（如 `修炼/闭关`），并通过 alias 保留短指令（发「闭关」仍可用）。
官方 `.help` 会按树展示；游戏内「帮助」卡同步按分组列出。

## 文案与插图

- 数据界面只摆数字与操作；气氛写在开场、闭关/出关、突破、抽签、奇遇、篇章、任务结算等节点。
- 高情绪节点可附樱花 API 随机图（`Config.images`，默认开；拉取失败则只发文字）。
- 自检 / golden 关闭插图，避免外网抖动。

跳过等待：将 `xianxia_queue.finishAt`、`xianxia_chain.finishAt`、`xianxia_user.seclusionStart` 设为过去时间。

管理员指令需 `authority ≥ 4`。高境界内容需相应 rank。

排版检查：`probe:style`（数据断言）+ `golden:check`（双通道快照）。

## 已知实现问题

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| set 回调内原生算术 | `row.exp + x` 得 NaN | 使用 `$.add` |
| timestamp 赋 null | TS 类型错误 | 写入时 `as any` |
| 插件 tsconfig module | ESM 产物 require 失败 | 覆盖为 CommonJS |
| dispose 内 ctx.logger | 卸载时报错 | 模块级 Logger |
| seclusionStart 与 seclusionLast 混用 | 闭关时长显示 0 | 分字段维护 |
| send 路径半角 `<>` | 内容被当元素解析 | 玩家文案用全角 `〈〉` |
| 绕过 emit 返回 Line[] | Invalid content | 统一 emit |
| toLines 过滤空串 | 段落空行丢失 | 仅过滤 null/undefined/false |
