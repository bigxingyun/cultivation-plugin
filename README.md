# 修仙挂机 · Koishi 插件

> ## 🚧 开发中 · WORK IN PROGRESS
>
> **这是一个还在开发中的项目，不是能玩的成品。** 数值、数据结构、指令输出都在改，
> 存档随时可能不兼容，**请不要用于生产环境**。
>
> 当前状态：**骨架与数值闭环已跑通**（31 条指令 / 55 项自动化自检全绿），
> 但**叙事内容大量是占位文本**（192 条任务里 174 条、19 条任务链里 12 条还没写正文）。

一个跑在 [Koishi](https://koishi.chat) 上的中文修仙挂机游戏。

设计上只围绕一条约束：**QQ 官方机器人是被动平台，不能主动推送**。所以整个游戏
**不用任何定时器**——闭关修为、历练队列、链节点、每日重置全部在玩家下一次发言时，
按时间戳一次性惰性结算。你离线八小时再回来，收益一分不少。

## 现在能玩到什么

| | 内容 |
| --- | --- |
| 修炼 | 闭关挂机 → 修为池满 → 按概率突破，9 大境界 × 9 层 = **81 级** |
| 历练 | **二级菜单多选一**：列出候选任务（目的 / 档位 / 耗时 / 成功率 / 奖励），挑一个排队 |
| 每日 | 签到（连签 7 天一循环）· 抽签（凶也给故事）· 答题 · 奇遇二选一 · 天机推演 |
| 成长 | 7 品 × 5 类丹药 · 16 门功法（3 品阶）· 炼丹 / 喂丹 / 丹炉 15 级 |
| 叙事 | **7 条可玩任务链**（42 个节点，每节点 intro / progress / success 三段文本）· 图鉴 · 成就 |
| 规模 | 31 条指令 · 10 张数据表 · 192 任务 / 108 奇遇 / 54 凶签 / 60 问答 |

**数值是算出来的，不是拍的。** 全部公式集中在 `src/core/curves.ts` 一个文件里：
公比 1.037，`EP(1) = 16,500`，满级纯闭关 `ΣT(1..80) = 856.9 h ≈ 35.7 天`，
含突破失败折损 `≈ 58.0 天`。越级打高难度永远有意义——收益/时间比恒定。

## 快速开始

```sh
git clone git@github.com:bigxingyun/cultivation-plugin.git
cd cultivation-plugin
npm install
npm run dev          # 控制台在 http://127.0.0.1:5140
```

打开控制台，左侧「沙盒」里发指令（`koishi.yml` 配了 `prefix: ['.', '/']`，所以要带前缀）：

```
.修仙        建档 + 开场白
.闭关        开始挂机（离线照常累计）
.历练        出菜单，挑一个任务
.任务 收      结算并读故事
.状态 .出关 .突破 .签到 .抽签 .答题 .奇遇 .天机
.丹药 .服用 聚气丹 .功法 .升阶 .炼丹 .喂丹 .丹炉
.任务链 .接链 青云旧籍 .链进度 .看故事 青云旧籍 .图鉴 .成就
.待办 .帮助 .介绍
```

> 想跳过等待：直接改 `data/koishi.db`，把 `xianxia_queue.finishAt` /
> `xianxia_chain.finishAt` / `xianxia_user.seclusionStart` 设成过去的时刻
> —— 这就是惰性结算的好处，时间是从时间戳算出来的。

## 项目结构

```
├── koishi.yml                       ← 应用配置（插件唯一的加载出口）
├── external/
│   ├── koishi-plugin-demo/          ← 链路测试插件（可当骨架模板）
│   └── koishi-plugin-xianxia-idle/  ← ★ 游戏本体
│       └── src/
│           ├── core/curves.ts       ← ★ 全部数值公式的唯一来源
│           ├── game.ts              ← 数据模型 + 惰性结算 + 数值聚合
│           ├── data/*.ts            ← 生成物（由设计文档解析而来，不手写）
│           └── commands/*.ts        ← 31 条指令
├── 插件/基础/                        ← 设计文档（游戏设定 / 结构 / 图鉴 / 故事库）
└── scripts/
    ├── smoke-xianxia.ts             ← 全流程自检（55 项）
    ├── probe-style.ts               ← 数据界面排版探针（人工看）
    └── gen-*.mjs                    ← 把 插件/基础/*.md 解析成 src/data/*.ts
```

## 自检

```sh
npm run smoke:game   # 55 项，退出码即结论
npm run probe:style  # 把数据界面的原样输出打出来（调排版用）
```

自检用官方 `@koishijs/plugin-mock` 起假平台，把指令一条条发进去，断言回复**和落库结果**。
时间流逝靠直接改数据库时间戳模拟。覆盖从公式层（`EP(1)=16,500`、成功率回代、
`punch = 3×生命`）到全流程（建档 → 闭关 → 历练 → 结算 → 突破 → 每日 → 丹道 → 任务链 → 图鉴），
外加 10 张表落库完整性、权限拦截、以及一条**输出分层禁词扫描**。

## 开发约定

**设计文档是唯一真源，代码从文档生成。** 数值只准写在 `插件/基础/开发游戏设定.md`，
`src/core/curves.ts` 是它在代码里的唯一映射；`src/data/*.ts` 由 `npm run gen` 解析文档产出。
文档之间冲突时按权威顺序判定，发现冲突**报告而不是偷偷改数**。

**数据界面只摆数据，解释归帮助。** 规则、获取途径、"下一步做什么"一律进 `帮助 <指令名>`
或回复末尾的 `▸ 待办` 行。详见《游戏结构与命令设计.md》§4.4.1，自检第 40 项会拦禁词。

更多踩坑记录与实现细节见 [`docs/开发笔记.md`](docs/开发笔记.md)。
