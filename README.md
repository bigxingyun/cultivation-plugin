## 为什么这样设计

QQ 官方机器人是**被动平台**——不能主动推送。因此整个游戏**不用任何定时器**：

闭关修为、历练队列、链节点、每日重置，全部在玩家**下一次发言时**按时间戳一次性惰性结算。离线八小时再回来，收益一分不少。

| **叙事** | **7 条可玩任务链**（42 节点，每节点 intro / progress / success 三段文本）· 图鉴 · 成就 |
| **输出** | **纯文本 / Markdown 两条渲染路径共用一份内容**——QQ 官方机器人出 Markdown，其余平台出纯文本 |
| **规模** | 31 条指令 · 10 张数据表 · 192 任务 / 108 奇遇 / 54 凶签 / 60 问答 |

**数值是算出来的，不是拍的。** 全部公式集中在 `src/core/curves.ts`：

- 公比 1.037，`EP(1) = 16,500`
- 满级纯闭关 `ΣT(1..80) = 856.9 h ≈ 35.7 天`，含突破失败折损 `≈ 58.0 天`
- 越级打高难度永远有意义——收益/时间比恒定

## 快速开始

```sh
git clone git@github.com:bigxingyun/cultivation-plugin.git
cd cultivation-plugin
npm install
npm run dev          # 控制台 http://127.0.0.1:5140
```

打开控制台，左侧「沙盒」发指令（`koishi.yml` 配了 `prefix: ['.', '/']`，需带前缀）：

```
.修仙        建档 + 开场白
.闭关        开始挂机（离线照常累计）
.历练        出菜单，挑一个任务
.任务 收      结算并读故事
.状态 .出关 .突破 .签到 .抽签 .答题 .奇遇 .天机
.丹药 .服用 聚气丹 .功法 .升阶 .炼丹 .喂丹 .丹炉
.任务链 .接链 青云旧籍 .链进度 .看故事 青云旧籍 .图鉴 .成就
.待办 .帮助 .介绍
```

> **跳过等待**：改 `data/koishi.db`，把 `xianxia_queue.finishAt` /
> `xianxia_chain.finishAt` / `xianxia_user.seclusionStart` 设成过去时刻即可——
> 惰性结算，时间全从时间戳算。

## 项目结构

```
├── koishi.yml                       ← 应用配置（插件唯一的加载出口）
├── external/
│   ├── koishi-plugin-demo/          ← 链路测试插件（可当骨架模板）
│   └── koishi-plugin-xianxia-idle/  ← ★ 游戏本体
│       └── src/
│           ├── core/curves.ts       ← ★ 全部数值公式的唯一来源
│           ├── core/render.ts       ← ★ 输出层：纯文本 / Markdown 双路径
│           ├── game.ts              ← 数据模型 + 惰性结算 + 数值聚合
│           ├── data/*.ts            ← 生成物（由设计文档解析，不手写）
│           └── commands/*.ts        ← 31 条指令
├── 插件/基础/                        ← 设计文档（设定 / 结构 / 图鉴 / 故事库）
├── docs/输出/                        ← 双渲染黄金快照（golden 生成，可 diff）
└── scripts/
    ├── smoke-xianxia.ts             ← 全流程自检（60 项）
    ├── golden-render.ts             ← 双渲染黄金快照（65 条指令 × 2）
    ├── probe-style.ts               ← 数据界面排版探针
    └── gen-*.mjs                    ← 把 插件/基础/*.md 解析成 src/data/*.ts
```

## 自检

```sh
npm run smoke:game    # 60 项全流程，退出码即结论
npm run golden:check  # 65 条指令 × 两种渲染，逐字比对 + 数据指纹一致
npm run probe:style   # 打印数据界面原样输出（调排版用）
```

| 脚本 | 覆盖范围 |
| --- | --- |
| `smoke:game` | 公式层 → 全流程（建档→闭关→历练→突破→每日→丹道→任务链→图鉴）· 10 表落库 · 权限 · 禁词扫描 · 双渲染指纹 |
| `golden:check` | 冻结时钟 + 定种随机，断言纯文本/Markdown 快照逐字未变、数据指纹一致、无空回复 |
| `probe:style` | 13 个数据界面原样输出，人工看排版（自检不断言排版） |

## 开发约定

1. **设计文档是唯一真源** — 数值只写在 `插件/基础/开发游戏设定.md`，`src/core/curves.ts` 是唯一映射；`src/data/*.ts` 由 `npm run gen` 生成。文档冲突按权威顺序判定，**报告而不是偷偷改数**。

2. **数据界面只摆数据，解释归帮助** — 规则、获取途径、"下一步做什么"进 `帮助 <指令名>` 或 `▸ 待办` 行。详见《游戏结构与命令设计.md》§4.4.1。

3. **一份内容，两条渲染路径** — 指令只产出结构化行，纯文本与 Markdown 由 `core/render.ts` 按平台落字，**绝不各写一遍文案**。`render: auto`（默认）仅 QQ 官方机器人（`qq`）出 Markdown，其余出纯文本；也可强制 `text` / `markdown`。Markdown 只改排版、不改数据——`golden:check` 逐条断言指纹一致。详见 §4.4.2。

更多踩坑记录见 [`docs/开发笔记.md`](docs/开发笔记.md)。

## 已知限制

- 只在 **Koishi 4.18 + SQLite** 上测过，未测 MySQL / PostgreSQL
- 数值与叙事仍在调整，**存档不保证向后兼容**
- 依赖基础群/私聊收发，刻意不用任何主动推送能力
- **Markdown 仅在 QQ 官方机器人（群/单聊）验证过**；QQ 频道（`qqguild`）自动回退纯文本。若发不出消息，把 `render` 改成 `text` 即可——两条路内容完全一致
