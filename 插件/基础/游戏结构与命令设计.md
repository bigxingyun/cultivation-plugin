## 二、游戏结构

### 2.1 一句话结构

> **用时间换数值，用数值换概率，用概率换境界；境界越高，能看的故事越长。**

三条轴互相咬合，缺一条游戏都不成立：

| 轴 | 载体 | 玩家感知 | 提供方 |
| --- | --- | --- | --- |
| **时间轴** | `T(rank)` / 闭关 / 历练队列 / 任务链节点 | "挂一晚上有多少" | §4.1、§7.2、§8.4 |
| **数值轴** | `EP` / `R` / 属性 / 功法 / 丹药 | "我为什么变强了" | §4.2–4.4、§6、§10 |
| **叙事轴** | 历练碎片 / 奇遇 / 任务链 | "后来怎么了" | §7、§9.4、§8 |

**设计意图**：时间轴让玩家可以离开，叙事轴让玩家愿意回来，数值轴让"回来"有意义。三条轴各自独立调参——所以**改叙事绝不动数值，改数值绝不动叙事**。

### 2.3 资源闭环（每一类产出都必须有出口）

| 产出 | 产出速率（60 天口径） | 出口 | 出口容量 | 是否闭合 |
| --- | --- | --- | --- | --- |
| 修为 | 890.4 h × `R` | 突破消耗 `EP(rank)` | 100% | ✅ 主循环 |
| 丹药 | 约 200+ 颗（§11.1） | ① 服用（每品级每日 3 次）② 炼丹 ③ 喂丹 | ①+②+③ > 产出 | ✅ |
| 灵材 | 约 10–20 / 天 | ① 炼丹 `20N²` ② 功法升阶 `15n²`/`40n²` | 后期吃紧（刻意） | ✅ |
| 故事碎片 | 凶签 10% / 天 + 任务履历 | 天机推演（3 枚 / 次） | 需限流见 §4.5.C4 | ⚠️ 出口偏窄（§13 待议 8） |
| 功法 | 历练掉落 | 替换（顶掉旧的）+ 图鉴收集 | 48 门有限 | ✅ |
| 图鉴条目 | 链节点 + 奇遇 + 条目 | 只读展示 | — | 不参与经济 |

> **一处必须记住的设计红线**：灵材是**唯一**的"第三类资源"，且刻意只有一种。任何新增资源都要先回答"它会不会把每日 5 分钟变成整理背包 10 分钟"（§11.2）。

### 2.6 一个典型的一天（指令时序）

| 时点 | 玩家动作 | 指令 | 状态要求 | 耗时 |
| --- | --- | --- | --- | --- |
| 早上 | 看昨晚收获 | `任务` | 闭关态可读 | 20 s |
| 早上 | 签到 + 抽签 + 答前一日的题 | `签到` `抽签` `答题` | 两态皆可 | 60 s |
| 早上 | **出关** | `出关` | — | 1 s |
| 早上 | 结算突破（可能连续多次） | `突破` × N | 出关态 | 30 s |
| 早上 | 排当日历练队列（3–8 个） | `历练 <目的> <档位> <数量>` | 出关态 | 30 s |
| 早上 | 吃药 / 炼丹 / 升功法 / 喂丹 | `服用` `炼丹` `升阶` `喂丹` | 出关态 | 0–20 min（可选） |
| 中午 | 接一条链 / 收链上节点 | `接链` `链进度` | 出关态 | 20 s |
| 全天 | 奇遇触发时做二选一 | `奇遇 1|2` | 出关态 | 10 s / 次 |
| 晚上 | **闭关**（含离线整夜） | `闭关` | — | 1 s |

- **必做合计 ≈ 5 分钟以内**（§9.7 红线）；"出关办事"这一段是**唯一需要出关**的窗口，因此它天然有边界。
- **闭关 ≠ 暂停队列**：早上排入的历练队列在闭关后**照常离线推进**（队列一旦入队即独立于闭关状态）。
- **待办摘要**会把"你还没签到 / 有 2 个任务可收 / 可突破 3 次"顶到任意回复的末尾，所以玩家不会因为忘记上线动作而亏损（原则 8）。

### 3.2 三幕结构

| 幕 | rank | 境界 | 玩家的问题 | 幕末得到的答案 |
| --- | --- | --- | --- | --- |
| **一 · 发现** | 1–27 | 练气 / 筑基 / 金丹 | "这些刻痕、名字、账，是什么？" | 有一个**体系**在记名字，宗门只是它的一个点 |

### 3.4 遮蔽规则（"那边还有故事"是动机来源）

| 链状态 | 玩家看到的 | 看不到的 |
| --- | --- | --- |
| `locked` | 链名 + 一句模糊描述 + **解锁条件的量化提示**（"需 rank ≥ 28"／"需先完成《名册》"） | 链首引子、节点标题、任何剧情 |
| `available` | 以上 + 完整的链首引子（**可反复查看**，§8.3）+ 节点数 + 预计总时长 | 节点标题与正文 |
| `active` | 以上 + 当前节点名、`progress` 段、倒计时 | 后续节点 |
| `completed` | 全部节点可回看（`看故事`），图鉴条目已解锁 | — |

- `locked` 的模糊描述**必须由链定义显式给出**（`blurb` 字段），不要用自动截断——自动截断会把伏笔漏出去。
- **不要全隐藏**：全隐藏会让玩家不知道"该往哪推"（§8.3）。
- `itemReq` / `flagReq` 类的解锁条件，对未持有者显示为"**？**"而不是条件内容（防止剧透），但必须在 `天机` 推演里给出线索。

## 四、命令结构

### 4.1 调用方式（决策 P-1）

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 前缀 | **`/` 为主，`.` 兼容**（`prefix: ['/', '.']`） | QQ 群习惯用 `/`；裸文本不触发 |
| 直呼 | **支持 `@机器人 <指令>`**（`session.stripped.appel`） | 群聊最自然的调用方式；与前缀并存不冲突 |
| **不采用无前缀** | ❌ | `状态` / `帮助` / `任务` / `签到` / `答题` 都是群聊高频日常词，无前缀必然误触 |
| 参数分隔 | 空格；`/历练 打怪 玄 3` | |
| 大小写 | 英文代号不区分大小写 | `combat` = `COMBAT` |

> ⚠️ **一处必须先定的后果**：一旦开启无前缀，所有含"闭关/状态/任务"的**正常聊天**都会被解析成指令。如果群友的聊天内容里出现这些词，插件会刷屏回复。**因此本文按"有前缀"设计全部规格**；若最终决定无前缀，必须额外提供 `黑名单/白名单频道` 配置项。

### 4.2 命名规范

| 规则 | 说明 |
| --- | --- |
| 主名 | **中文动词/名词，1–3 字**（闭关、出关、突破、历练…），不用拼音、不用英文 |
| 别名 | 每条最多 2 个中文近义别名（如 `状态`↔`属性`），另加 1 个英文别名供英文键盘用户（`help`、`status`） |

| 子命令 | 只有管理指令用子命令（`修仙管理 查询`）；**游戏指令一律不做子命令层级**——挂机游戏的玩家不查手册 |
| 冲突 | 指令名不得与 Koishi 内置指令（`help`、`status`、`echo`…）重名；已核对：`status` 冲突 → 英文别名用 `me` 而非 `status` |

| 概率 | **显示取整/1 位小数，计算用分数**（§5.1 定稿）。禁止用显示值参与计算 |
| 失败回复 | 一律 **不 @ 人**、不带情绪词、必须给出"下一步该做什么" |
| 私聊/群聊 | 群聊里返回的数据只属于调用者；管理指令在群聊里的输出必须显式写出目标用户 ID |

#### 4.4.1 数据界面 vs 帮助界面（输出分层）

分界线只有一句：**这一行是玩家现在要看的数，还是我们要教他的规则？**

| 类别 | 例子 | 放哪 |
| --- | --- | --- |
| 标签 + 数值 | `增速　2.50 /秒`、`战力　303`、`修为　0 / 16,500` | 数据界面 |
| 作用域 / 单位 / 时长 | `（剩 2 分钟）`、`下一次突破`、`30 分钟`、`（保底 30%）` | 数据界面，贴在数值后 |
| 状态 | `闭关　未开启`、`已是上品　封顶` | 数据界面 |
| 拆解（**多因子才有**） | `增速　3.75 /秒　（境界 ×2.50　功法 ×1.20）` | 数据界面 |
| 规则 / 获取途径 / 为什么 | 「功法和丹药只能从历练获得」「喂一颗 N 品丹给 N² 点经验」 | `帮助 <指令>` |
| 劝告 / 评价 / 安慰 | 「这是资源转换，不是赌博」「再攒一批就行」「这条路比你想的长」 | 删 |
| 下一步该干什么 | 「现在可以突破 / 历练 / 用丹药」 | 删 —— 已由 `▸ 待办`（§4.6）承担 |
| 操作本界面必需的那一下 | `发编号选择`、`发「奇遇 1」或「奇遇 2」` | 数据界面，限一行 |

三条硬约束：

1. **`▸ 待办` 是唯一的"然后呢"通道。** 数据界面里不写「发 X 做 Y」——待办行每次都算好了。只有离开提示就无法操作控件时（菜单、二选一、答题）才留一行操作提示，且不含理由。
2. **括号只装数据。** `（境界 ×2.50）`、`（剩 2 分钟）`、`（保底 30%）` 合法；`（修为不增长，发「闭关」开始）` 非法。
3. **只有一个因子时不显示拆解。** 练气期裸号的 `增速　2.50 /秒　（境界 ×2.50）` 是废话——它和上一行说的是同一件事。

**落地检查**：自检第 40 项对 12 个纯数据界面（状态/历练/任务/丹药/功法/丹炉/待办/图鉴/成就/任务链/链进度/签到）扫描 7 个禁词（`只能从`｜`——`｜`不是赌博`｜`不必守着`｜`记住了就是收获`｜`留到概率更低`｜`离线照常累计`），命中即失败；含剧情正文的界面（答题/抽签）只查其中 5 个（正文里的破折号是内容，不是我们写的说明）。

### 4.5 逐条指令规格

#### A1 `修仙` ｜ 建档与开场（M1）

- **行为**：若 `user` 无记录 → 建默认档（`rank:1 exp:0`）并返回开场白；已有记录 → 一行当前进度 + `▸ 待办`。
- 开场白**必须包含四件事**：这是什么、怎么开始（`闭关`）、**不用一直在线**、下一步建议。开场白是**引导界面**，不受 §4.4.1 的"只摆数据"约束；已有记录的复访是数据界面，只给一行。
- 输出（首次）：

```
【青云宗 · 杂役院】
你是青云宗扫东院的杂役。你没有名字，没有功法，也不配参加问道试。
但你捡到了一块不该出现的玉简。

修为会自己往前走，不必守着——关掉手机也在涨：
　/闭关　开始挂机（离线照常累计）
　/状态　看看自己
　/历练　出门做事，攒功法和丹药（会给一份菜单）

▸ 待办：今日未签到 · 历练次数剩 3 · 未闭关，修为不涨
```

- 输出（已有记录）：

```
【筑基三层】修为 24,113 / 40,189　60.0%
▸ 待办：可突破 1 次
```

#### A2 `闭关` ｜ 开始挂机（M1）

- **行为**：① 先 `settleSeclusion()`（只结算上次结算点至今这一段）；② 置 `seclusionStart = now`、`seclusionLast = null`。
- **幂等**：已闭关 → 提示而非报错，并附当前已挂时长。
- **状态门禁**：如果玩家正处于**出关态且有未决写操作**（如队列已排满未处理）→ 不阻止，只提示。
- 输出：

```
【闭关 · 开始】
增速　2.50 /秒
本层还需　1 小时 50 分
```

#### A3 `出关` ｜ 结算并暂停（M1）

- **行为**：结算 → `seclusionStart = null`、`seclusionLast = null` → 返回本次闭关的**时长 / 获得修为 / 当前进度**。
- **实现要点（踩过）**：`settleSeclusion()` 每次交互都会跑，它**只能移动 `seclusionLast`（结算游标），绝不能动 `seclusionStart`**。早期版本把起点也一起推到 now，「出关 合计」和「状态 已挂」就恒显示 `0 秒`——玩家挂了 1 小时 22 分，界面说他刚闭关。合计时长 = `now − seclusionStart`，自上次交互以来的增量为 `settled.sec`，两者不是一回事。
- 输出：

```
【出关 · 合计 1 小时 22 分】
修为　+38,120
当前　24,113 / 40,189　60.0%
```

> **为什么闭关要"只读"**：见 §2.6。闭关期照常允许签到/抽签/答题（每日仪式，1 分钟），但**突破、历练、丹药、功法、丹道、链的推进都必须出关**——否则 `闭关` 只是一个没有代价的开关，`出关` 永远不会被使用（这是 §7 差异清单里那只"隐形的设计空洞"）。

#### A4 `状态` ｜ 玩家唯一需要看懂的界面（M1）

- **行为**：惰性结算 → 输出境界 / 修为 / 增速 / 闭关状态 / 属性 / 战力 / 功法 / 丹药 / 资源。
- **强制要求**：加成**逐项拆开**（境界 / 功法 / 丹药 / 事件），因为"玩家看不懂自己为什么变强就会流失"（§14）；但按 §4.4.1 约束 3，**只有一个因子时不显示拆解**。
- **战力不再给出"凡档要求 / 帝档要求"**：档位要求属于"我打不打得过"，而这个判断在别处已经用**成功率**直接给出（§B1 菜单）。同一个数在两个界面里换算两次，是数据界面的冗余。
- 输出（rank 12 实例，数值均按公式实算）：

```
【状态】筑基三层　12 / 81
修为　24,113 / 40,189　██████░░░░　60.0%
增速　11.62 /秒　（境界 ×4.08　功法 ×2.19　悟道 ×1.30）
闭关　进行中　已挂 1 小时 22 分
生命　149　攻击　149　闪避　3.60%
战力　447
──────
功法　太乙剑典 · 中品　×2.19
特效　力魄 攻击 +24%　轻身 闪避 +3.6pt
丹药　悟道 ×1.30（剩 12 分钟）
灵材　1,204　碎片　7　丹炉　6 级
▸ 待办：可突破 1 次 · 今日未签到
```

#### A5 `突破` ｜ 概率与时间的兑换点（M1）

- **前置**：`exp ≥ EP(rank)`（否则报『修为不足』并**换算成还需多久**）；`rank < 81`。
- **行为**：消耗 `EP(rank)`；概率 `clamp(基础 + Σ丹药 + 连败 15pt, 0.05, 0.95)`；成功 → `rank+1`、`exp -= EP(旧rank)`、清连败；失败 → `exp = exp - EP(旧rank) + 0.7×EP(旧rank)`（等价于退回该层 70% 位置）、连败 +1。
- **可连续**：`exp` 允许跨多个池累积（原则 8：离线不设上限）；一次 `突破` 只升一层，成功后可立即再发。
- **概率拆解只列非零项**（`丹药 +0.0pt` 不显示）；**连败计数以 `N / 3` 的形式给出**，不写"连败 3 次后下一次 +15pt"这类规则句。
- 成功输出：

```
【突破 · 筑基三层 → 筑基四层】
成功率　86.7%　基础 86.7%
判定　✔ 成功
消耗　修为 40,189　剩余 3,208
──────
当前　筑基四层　13 / 81　下一层 43,487
```

- 失败输出（**必须兑现"只损失时间"**）：

```
【突破 · 筑基三层】失败
成功率　86.7%　基础 86.7%
判定　✘
修为退回 70%　28,132 / 40,189
连败　1 / 3
```

#### B1 `历练` ｜ 唯一的资源入口（M2）

> **形态：二级菜单 + 多选一。** 玩家不该盲排任务——他要先看到"有哪几件事可做、各要多久、成功率多少"，再挑一件。

- **用法**（四种形态，同一个指令）：

| 输入 | 行为 |
| --- | --- |
| `历练` | **出菜单**：列出 4–6 个候选任务，每个带「目的 · 档位 · 任务名 · 耗时 · 成功率 · 修为奖励」 |
| `历练 <编号>` | 排队菜单里的第 N 个。**排的就是玩家看到的那一个**，不是重新随机抽 |
| `历练 换` | 换一批候选（菜单不消耗次数） |
| `历练 <目的> [<档位>] [数量]` | 批量快捷方式：只给目的 → 列出该目的的候选；给全 → 直接排 N 个 |

- **候选怎么来**：四个目的各一条（档位 = 当前境界）+ 一条**挑战**（档位 +1）+ 一条**轻松**（档位 −1），去重后按 (目的, 档位) 唯一。菜单**不落库为表**，只把候选的 `missionId` 列表存在 `user.pendingMenu` 里——`missionId` 自带 `境界-档位-目的`，不需要额外字段。
- **目的**：`打怪`(combat) / `药田`(farm) / `修习`(train) / `复合`(compound)。
- **档位**：`凡 黄 玄 地 天 仙 帝` = `1..7`；档位 ≠ 境界，**越级永远有意义**（收益/时间比恒定，§7.1）。
- **行为**：**原子扣减次数**（`set` + `$gte` 条件 + 判 `matched`，见指南 §5.6）→ 入队 `mission_queue`（串行：第 n 个的 `finishAt` = 前一个的 `finishAt` + 该档位耗时）→ 回到菜单，方便连续挑。
- **耗时**：`120 秒 × 1.5^(档位−1) × 1.037^(rank−1)`。
- **菜单输出的字段是"决策所需的全部信息"**：

```
【历练 · 今日剩 3 / 3 次】
① 打怪·凡档　后山赶兽　　3 分钟　95.0%　修为 495
② 药田·黄档　药圃点种　　4 分钟　95.0%　修为 990
③ 修习·玄档　清扫藏经阁　7 分钟　76.0%　修为 1,650
④ 复合·地档　押送药箱　　11 分钟　68.7%　修为 2,640
⑤ 打怪·天档　追踪野狼　　17 分钟　63.0%　修为 3,630
──────
发编号选择 · 「历练 换」换一批
```

- **末尾那行是"操作本界面必需的那一下"**（§4.4.1 约束 1 的唯一豁免口），且**只有这一行**：批量快捷方式、掉落地图、越级为什么划算，全部归 `帮助 历练`。早期版本在菜单里贴了 3 行说明，等于把帮助页塞进了数据页。
- **次数用尽时不出菜单**，只给一行数据：`【历练】今日次数已用尽　3 / 3`。「明日 0 点重置」「可以去推任务链」都属于规则与建议，归帮助与 `▸ 待办`。

- **为什么不做成"选目的 → 选档位"的三级树**：那会让玩家点两次才看到任务名，而"任务名"才是他真正在挑的东西（名字背后是故事）。**注意：玩家挑的是任务，不是过滤器。**
- **为什么保留批量快捷方式**：老玩家与测试需要一次排满今日次数；它走的是同一套排队与计时逻辑，只是跳过了菜单。
- 错误分支：

| 情况 | 文案 |
| --- | --- |
| 次数不足 | `【次数不足】今日 3 / 3` |
| 档位非法 | `【档位不对】可用 凡 黄 玄 地 天 仙 帝 或 1–7` |
| 编号越界 | `【没有第 7 个】菜单里只有 5 个。` + 重出菜单 |
| 未出关 | `【闭关中】发「出关」后可操作` |
| 菜单过期/数据丢失 | 自动重出菜单（不报错），顶行只写 `【还没有菜单】` |

#### B2 `任务` ｜ 队列与收取（M2）

- `任务` → 队列（进行中 + 已完成未读计数）。
- `任务 收` → 惰性结算全部到点任务，**按 `mission_log` 未读段依次输出**（成功每条 ≤120 字 + 奖励；失败给保底 30%），并把 `missionLogReadAt = now`。
- **结算与读取分离的原因**：奖励在**任意交互时**就已入库（原则 8，绝不丢），文本读取只是只读回放 → 不需要把故事正文写进数据库（§5.2）。
- 输出（`任务 收`）：

```
【任务结算 · 2 个】

打怪 · 玄档　追踪野狼　✔
　你顺着爪印追到一处山洞。洞里有狼，也有三只崽子。你没有进去。
　+修为 7,547　+灵材 6　+功法：赤炎诀（地品 · 中品）

复合 · 玄档　修补篱笆　✘
　你补到第四处时天降大雨，泥浆把前两处又冲开了。你蹲在雨里，
　就着雨水把箭头上的泥搓干净。
　+修为 2,264（保底 30%）　+灵材 2

合计修为 +9,811
```

> 队列界面里**没有**"发「任务 收」结算并读故事"这类指路语——到点了没收是 `▸ 待办` 会算出来的（`N 个任务可收`），数据界面重复一遍就是噪音。

#### B3 `放弃 <序号>` ｜ 撤销未开始的任务（M2，可选）

- 只允许放弃**尚未开始**（`finishAt - 耗时 > now`）的任务；**返还该次次数**。理由：放弃不该变成惩罚（原则 7）。
- 已开始的任务不可放弃（避免"看快失败了就撤"的作弊）。

#### C1 `签到` ｜ 连签 7 天（M3）

- 每日 0 点刷新；第 7 天大奖；**断签不清零，回退 2 格**（§9.1）。
- 奖励**按当前 rank 结算**（不会因为早期签到而在后期无用）。
- 输出：

```
【签到 · 第 4 天（连签）】
修为　+4,823
明日　第 5 天　历练次数 +1　当日
已连签 4 天 ████░░░
```

#### C2 `抽签` ｜ 每日仪式（M3）

- 概率：大吉 5% / 吉 20% / 小吉 30% / 平 35% / 凶 10%。
- **凶只给故事，不给惩罚** → 给 1 枚故事碎片 + 一条签文。
- 小吉 = 今日首次历练必成功（**存为 `flag`，在结算时消费**）。
- **签文行必须紧跟实际生效的效果行**：大吉/吉 给增速 buff 的倍数与时长，小吉给护道，平给具体修为数，凶给碎片与签文。早期版本只印 `DRAW_TABLE.text` 的散文（"修为增速 ×1.5，持续 1 小时"），玩家看不出这一签到底改了什么数。

```
【抽签 · 吉】
增速　×1.25　1 小时
签文　石上有痕，痕不是给你看的。
```

#### C3 `答题` ｜ 把叙事变成可记忆的内容（M3）

- `答题` → 出当天的题（**按服务器日期确定性抽取**，绝不用 `Math.random()`，否则刷新换题）。
- `答题 A|B|C` → 判定；答对给奖励，**答错无惩罚**，并给出解释与出处。
- 一题只能答一次（`user.quizAnsweredAt` 当日）。
- **解析文本是内容**，不受 §4.4.1 约束（它是题目的答案说明，不是我们写的操作说明）；但"答错不罚——记住了就是收获"这类安慰语删掉。

```
【每日问答 · Q1-04】
后山药田的主人是谁？
　A. 老周　　B. 老柯　　C. 赵秉
发「答题 A」「答题 B」「答题 C」
```

#### C4 `奇遇` ｜ 被动事件与二选一（M3）

- 触发：闭关或历练结算时有 **8%** 概率入队一条待决奇遇（`pendingEvent`）；**不在群里主动播报**，只在待办摘要里提示。
- `奇遇` → 显示待决事件；`奇遇 1|2` → 执行选择。**未决奇遇最多 1 条**（避免积压）。
- 二选一没有绝对最优解（§9.4）。

```
【奇遇 · 断崖下的一株灵草】
采摘：随机丹药 ×1，但修为增速 -10%（1 小时）　即时资源
上报宗门：修为 = 25% × EP(rank)，无副作用　稳定进度
发「奇遇 1」或「奇遇 2」
```

> 末尾的 `即时资源` / `稳定进度` 是**选项的分类标签**（数据），不是推荐（推荐会破坏 §9.4"没有绝对最优解"）。

#### C5 `天机` ｜ 碎片出口（M6）

- 消耗 3 枚故事碎片 → 随机给一条**关于未解锁内容**的具体提示（某个未获得功法的线索 / 某条链的下一环 / 某个奇遇条件）。
- **纯信息，不产出数值**（不破坏经济）。
- 输出（含**去向**，避免"抽到没用的"）：

```
【天机推演 · 碎片 -3　剩 12】
『第八垄的收成，从来不送丹房。』
《第八垄》　未解锁 · rank ≥ 39
```

#### D1 `丹药` ｜ 背包（M4）

```
【丹药 · 灵材 186 · 碎片 15】
修为　聚气丹 ×12　玄元丹 ×3
淬体　淬体散 ×5
突破　破障丹 ×2　凝神丹 ×1
悟道　悟道丹 ×2（剩 28 分钟）
护道　—
```

> 空背包只回 `（空）`。「丹药只能从历练和签到/问答/奇遇里来」是帮助内容。

#### D2 `服用 <丹药> [数量]` ｜ 资源出口（M4）

- 修为丹：`效率(品级) × EP(当前 rank)` —— **绝不用固定值**（§10.1，断言 19）。
- 突破丹：**先加算再 `min(0.95,·)`**；若当前概率已 ≥95% → **拒绝服用**（§5.4，断言 10）。
- 冷却：同类 3 分钟；每品级每日 3 次。
- 效果行只写**变化后的数与作用域**，不写公式也不写取舍建议：

```
【服用 · 破障丹（一品 · 突破）】
突破成功率　+5.0pt　下一次突破
今日该品级已用 1 / 3　同类冷却 3 分钟
```

#### D3 `功法` / D4 `升阶` ｜ 成长主线（M4）

- `功法` → 当前功法（模板 + 品阶 + 倍率 + 特效 + 逐项拆解）+ 已收集进度（`x / 48`）。
- `升阶` → 消耗 `15n²`（下→中）/ `40n²`（中→上）灵材 + **修为**（`30%` / `60% × EP(rank)`）；下→中 100% 成功、中→上 90%；失败**不掉材料**，只损失修为（回退 50%）；成功后 1 小时冷却。
- 60 秒内可撤销？**不做**（升阶是确定性的，不需要撤销）。

#### D5 `炼丹` / D6 `喂丹` / D7 `丹炉` ｜ 资源出口（M6）

- `炼丹`：`3 颗 N 品 + 灵材 20N² → 1 颗 (N+1) 品`，成功 100%，无冷却；七品封顶。
- `喂丹`：喂一颗 N 品给 `N²` 点丹药经验；**只增不减**。
- `丹炉`：15 级门槛合计 **402,385**；每级加成见 §11.4。
- 批量：`炼丹 聚气丹 5` 一次炼 5 份（材料不足时按最大可炼数执行并告知）。

#### E2 `接链` / E3 `链进度` / E4 `看故事` / E5 `放弃链`

- `接链 <链名>`：校验 `rankMin` / `chainDone` / `itemReq` / `flagReq` → `available → active`，返回**链首引子**（400 字，一次读完）。

### 4.6 待办摘要（零主动推送的落地机制）

**背景**：QQ 官方机器人是被动平台，**不能靠定时推送**（§9.7）。因此"该突破了"这类提示必须**搭在玩家自己的发言上**。

| 项 | 规则 |
| --- | --- |
| 位置 | 任意指令回复的**最后一行**（前面加一条 `──────` 与正文分开） |
| 格式 | `▸ 待办：<项 1> · <项 2> · <项 3>`（每项 ≤12 字） |
| 条目 | ① `可突破 N 次`（池满）② `N 个任务可收` ③ `N 个链节点可看` ④ `今日未签到` ⑤ `有 1 条奇遇待选` ⑥ `历练次数剩 N` ⑦ `未闭关，修为不涨` |
| 优先级 | 按上面的次序生成，**⑦ 排最后**——它是"该收工了"的提醒，不该挤掉"现在能做的事" |
| 上限 | 最多 **3 项**（超出只显示前 3，完整列表用 `待办`） |
| 抑制 | `待办` / `帮助` / `介绍` **不附加**（它们本身就是清单或说明书）。`状态` / `任务` **故意附加**——`状态` 是玩家最常发的指令，待办搭在它上面才有送达率 |
| 重复 | **不做去重/冷却**。同一项连续出现是有意的：待办是唯一提示通道（§4.4.1 约束 1），压掉它就等于压掉引导。它被截到 3 项，重复的代价本来就很小 |
| 禁止 | 不 @ 人、不单独发送、不在他人指令的回复里出现 |

**为什么不做"到点自动私聊"**：主动消息配额极少，且一旦被平台限制，玩家会以为游戏坏了。**把主动性交给玩家**（§9.7）。

**为什么必须有 ⑦「未闭关」**：数据界面里删掉了「修为不增长，发闭关开始」这类解释（§4.4.1），而 `闭关　未开启` 这个状态本身不说明后果。信息不能两头都丢——删一处必须在 §4.6 补一处。
